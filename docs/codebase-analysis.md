# Sonata Codebase Analysis

Snapshot of workspace structure, modular splits across Rust and Android, resolved Faz 1–5 milestones, and open refactoring opportunities (`v1.0.7+`).

## 1. File-Size and Modularity Breakdown

The Rust workspace contains **95,747 Rust lines** across **5 crates** (`sonata-core`: 32,673 total / 31,911 src; `sonata-runtime`: 15,838 total / 14,391 src; `sonata-desktop`: 30,951; `sonata-tui`: 12,240; `sonata-android`: 4,045 total / 3,880 src), paired with **69,361 Kotlin main lines** (excluding generated UniFFI bindings) and **5,197 Kotlin test lines** under `android/`.

Large Rust and Android monoliths have been split into single-responsibility modules:

| Component | Split modules |
|---|---|
| `sonata-core` engine & providers | `providers/ytmusic/{mod (2,909), parsers/{mod (1,263), home (509), artist (685), video_sync (517)}, browse, album, search}.rs`, `providers/spotify/{mod, embed}.rs`, `providers/hifi/{innertube (1,459), cipher, matching, cache}.rs`, `providers/servers/{mod, subsonic, jellyfin, smb, webdav}.rs`, `providers/jiosaavn.rs`, `lyrics/{mod, lrclib, providers, translate, ttml}.rs`, `motion.rs`, `player/{mod, coordinator, tasks, precache}.rs`, `scrobble.rs`, `stats.rs`, `connect.rs`, `playlists.rs` |

## 2. Resolved Security, Reliability & Architecture Milestones (Faz 1–5)

| Area | Verified implementation in codebase |
|---|---|
| **ADR-0001 crate boundaries** | Extracted Linux-only adapters into [`crates/sonata-runtime`](../crates/sonata-runtime); eliminated subprocess launches, `cfg!(target_os = "android")` provider branches, and global path/policy statics from [`crates/sonata-core`](../crates/sonata-core); enforced automatically by [`scripts/check_boundaries.sh`](../scripts/check_boundaries.sh). |
| **Shared Linux `PlaybackSession` & `watch` progress** | Consolidated TUI and Desktop `mpv` orchestration into [`sonata-runtime/src/player/session/mod.rs`](../crates/sonata-runtime/src/player/session/mod.rs) (modularized in Faz 5 with `controls.rs`, `quality.rs`, and `tests.rs`), supporting gapless playback, 0–12 s crossfade ramps (bypassed in Video mode), sleep timer fade-out, and coalesced `PlaybackProgress` `watch` updates. |
| **Cancellable async UniFFI bridge** | [`crates/sonata-android/src/lib.rs`](../crates/sonata-android/src/lib.rs) exports `#[uniffi::export(async_runtime = "tokio")]` futures with zero `Runtime::block_on`, paired with `SonataEngineGateway.kt` and `PlaybackOrchestrator.kt` generation isolation. |
| **Consolidated providers, servers & offline downloads (Faz 1–3)** | Unified YTM parsers (split in Faz 5 into `ytmusic/parsers/{mod, home, artist, video_sync}.rs`), JioSaavn DES-ECB/320 kbps matching, `MotionMedia` discovery, self-hosted Subsonic/Jellyfin/SMB/WebDAV servers (`providers/servers/`), personal playlists (`playlists.rs`), Discord Rich Presence (`discord.rs`), and Linux offline downloads (`downloads.rs`). |
| **Connect, Scrobbling & Listening Stats (Faz 4)** | Added Sonata Connect LAN handoff + HMAC-SHA1 6-digit PIN pairing (`sonata-core/src/connect.rs`, `sonata-runtime/src/connect.rs`), Last.fm & ListenBrainz scrobbling (`scrobble.rs`), on-device SQLite `StatsStore` (`stats.rs`, Desktop `views/stats.rs`, TUI stats modal, Android Stats UI), and Android Auto `MediaLibraryService`. |
| **Faz 5 modularization, Flatpak & cross-platform plan** | Decomposed `ytmusic/parsers.rs`, `player/session.rs`, and `views/fullscreen.rs` (`fullscreen/{mod, ambient, lyrics, controls}.rs`) with 100% preserved exports and tests; added Flatpak packaging manifests ([`packaging/flatpak/dev.sonata.Desktop.yml`](../packaging/flatpak/dev.sonata.Desktop.yml), [`dev.sonata.Desktop.metainfo.xml`](../packaging/flatpak/dev.sonata.Desktop.metainfo.xml)) and documented the macOS/Windows `sonata-runtime` shim plan in [`docs/cross-platform.md`](cross-platform.md). |
| **Cookie permissions, backups & redaction** | [`crates/sonata-core/src/auth/cookies.rs`](../crates/sonata-core/src/auth/cookies.rs) enforces `0o600`/`0o700` permissions; [`redaction.rs`](../crates/sonata-core/src/redaction.rs) scrubs headers/URLs; `SonataPreferences.exportBackupJson()` excludes credentials. |
| **Android FOSS posture & APK updater** | Disabled `dependenciesInfo` in `android/app/build.gradle.kts`, omitted tracking/analytics SDKs, and scoped `REQUEST_INSTALL_PACKAGES` strictly to user-initiated GitHub Releases APK updates via `ApkUpdater.kt` + `FileProvider`. |
| **Cross-platform test coverage** | **289 Rust unit & integration tests** plus **4 doc-tests** (**293 total**, all passing via `cargo test --offline --locked`: `sonata-core`: 148 unit + 16 integration + 4 doc-tests, `sonata-runtime`: 43 unit + 10 integration, `sonata-desktop`: 39 unit, `sonata-tui`: 21 unit, `sonata-android`: 10 unit + 2 integration) and **86 Android Kotlin tests** (**84** JVM unit tests passing across **12** suites via `./gradlew testDebugUnitTest` + **2** instrumented tests in `NativeEngineInstrumentedTest.kt`). |

## 3. Current Open Maintenance & Refactoring Opportunities

1. **Split remaining oversized UI & backend files**: `SonataViewModel.kt` (7,983 lines), `CategorizedSettingsSheet.kt` (3,915 lines), `sonata-android/src/lib.rs` (3,872 lines), `sonata-desktop/src/backend/mod.rs` (3,441 lines), and `ytmusic/mod.rs` (2,909 lines) are strong candidates for targeted submodule decomposition.
2. **Execute macOS and Windows `sonata-runtime` shims**: Implement the CoreAudio/AVFoundation/Keychain/`NSWindow` and WASAPI/Credential Manager/Mica/`AppUserModelID` shims outlined in [`docs/cross-platform.md`](cross-platform.md).
3. **Expand Android Compose UI / instrumented coverage**: Build on `NativeEngineInstrumentedTest.kt` and the `84` JVM unit tests with Compose UI behavior tests for navigation, settings search, and player sheets.
